منهجية الأمان الرباعية (لماذا هذه النتيجة موثوقة)

1
التكرار بالبصمة: مقارنة SHA-256 لكل ملف — لا تُحسب "مكررة" إلا المتطابقة حرفياً بايتاً بايت.
2
المرجعية بالمطابقة الكاملة للمسار: لا يُحذف ملف إلا إذا لم يذكره أي ملف تشغيل (HTML/JS/CSS/JSON/YML/VCF) ولا بسياق مجلده، حتى لا يُحذف الملف الصحيح لأن توأمه مُشار إليه.
3
الفحص الديناميكي: بحث عن جذوع الأسماء داخل الكود لصدّ الاستدعاءات المبنية برمجياً مثل ${brandId}-brand-kit.zip — هذا الفحص أنقذ حزم brand-kits ومكتبة social-8k-branding كاملة (المستخدمة من محرك الحملات المجدولة ومن الكونسيرج) من حذف كان سيبدو منطقياً لكنه كان سيكسر الموقع.
4
التحقق اللحظي داخل السكربت: عند التشغيل على جهازك يعيد الفحص من جديد قبل كل حذف فردي، فإذا تغيّرت الحالة (ملف أصبح مرجعياً) يُتخطى مع تحذير تلقائياً.

📍 بطاقة المسار والطريقة (طبقها على جهازك)

1
نزّل الملف cleanup_sr_coresync.py من مجلد التسليم هنا، وضعه في جذر مشروعك — أي داخل: D:\I-Ai\App\S&R CoreSync For Intelligent Solutions\Project (بجانب index.html وtask.md مباشرة، وليس داخل أي مجلد فرعي).
2
افتح CMD أو PowerShell داخل هذا المجلد وشغّل أولاً الوضع التجريبي: python cleanup_sr_coresync.py --tier2 — سيعرض كل ما سيفعله دون حذف أي شيء.
3
إن اقتنعته، شغّل التنفيذ: python cleanup_sr_coresync.py --tier2 --apply — سيحذف الملفات، ويعيد فحص المرجعيات لحظياً قبل كل حذف، ويحدّث task.md وwalkthrough.md وworklog.md تلقائياً بحسب بروتوكول GEMINI.md.
4
ثم الرفع للبيئات الثلاث: git add -A ثم git commit -m "chore: الإنجاز 160 — التنظيف الشامل" ثم git push — أو استخدم أداة نشر_تلقائي_إلى_GitHub_Pages.bat لديك.
5
إن أردت حذف أرشيف السكربتات القديمة أيضاً: python cleanup_sr_coresync.py --tier2 --tier3 --apply (اختياري).

ملاحظة أمان: وضع التجريبي هو الافتراضي دائماً. أي حذف يُعاد فحص مرجعياته لحظة التنفيذ، وإن تغيّر شيء منذ اليوم يُتخطى تلقائياً مع تحذير.
