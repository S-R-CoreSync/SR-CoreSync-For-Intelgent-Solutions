```
ckb\index.html   overlay=0  peekIds=0  showStudioPeekCalls=12  sr-master-shell=0
```

## 4. لماذا لم أُصلحه في المرحلة 175

- قواعد المشروع تمنع إصلاح الأعطال القائمة «بالمرور» داخل مرحلة أخرى: يوسّع سطح المراجعة ويخلط ما هو جديد بما هو قديم.
- الإصلاح الصحيح ليس سطراً واحداً: يحتاج نقل محرك المعاينة كاملاً (بيانات 8 قطاعات، 3 أوضاع عرض، شريط المقارنة `toggleBenchmarkView`، ونافذة بـ11 معرّفاً) إلى وحدة مستقلة + مسارات أصول نسبية للصفحات الفرعية + إضافتها إلى 29 صفحة + تحقق بصري.

## 5. الخياران المقترحان (اختر واحداً)

**الخيار أ — استعادة الميزة (الأنصح للمنتج):**
1. استخراج المحرك إلى `js/sr-studio-peek.js`: خريطة القطاعات + `showStudioPeek` / `closeStudioPeek` / `switchStudioPeekTab` / `applyStudioPeekView` / شريط المقارنة، مع حقن نافذة `#srStudioPeekOverlay` تلقائياً إن لم توجد.
2. حلّ مسار الأصول نسبياً (`./assets/` للجذر و`../assets/` للصفحات الفرعية) بدل المسارات المطلقة.
3. إضافة وسم السكربت إلى الصفحات الـ28 + الإبقاء على `index.html` كما هو (الوحدة لا تعيد التعريف إن وُجد).
4. معيار القبول: `browser_console_audit.mjs` → 30/30، ولقطة شاشة واحدة لكل لغة عيّنة.

**الخيار ب — إزالة الميت (الأسرع والأصغر):**
حذف `onclick="showStudioPeek(...)"` من أزرار القطاعات في الصفحات الـ28 وتحويلها إلى روابط لأقسام موجودة، حتى تُنقل النافذة مع خط أنابيب التعريب. معيار القبول نفسه.

**في الحالتين:** لا يُعدّل `browser_console_audit.mjs` ولا تُخفَّف قاعدته — الفحص صحيح والماركب هو الخاطئ.
